## Features and design

The existing `/trips/:tripId/itinerary` retains trip information, days, timeline, CRUD, order, notes, local-save feedback, date safeguards and backups. Desktop adds a complementary map card; 1024px moves days above the two-column workspace; below 1024px an accessible Itinerary / Map & routes toggle replaces the split. Both views retain editing state. The map opens on request, preserving a lightweight initial experience and avoiding unrequested third-party tile traffic.

MapLibre GL JS **6.16.0** is pinned, with its official Vite `?worker&url` setup and dynamically loaded CSS/renderer/worker. OpenFreeMap's public Positron style requires no account/key. Zoom, fit, destination marker, numbered day markers, visible source attribution and clear loading/WebGL/tile/module errors are implemented. An accessible location list duplicates essential map interactions. Marker IDs follow activity IDs, not array indices. Cards and markers synchronize selection; marker activation focuses/scrolls the activity, and mobile returns to the list. Day changes update markers and clear out-of-day selection. Missing coordinates remain unknown and offer a real location edit action.

MapController updates keyed marker objects without recreating the map, handles route overlays/fit/selection, and removes markers/listeners/map on cleanup. ResizeObserver and RAF cleanup handle toggles/layout changes. Reduced motion disables animated panning. Fit includes actual route geometry and handles nearby points across the antimeridian. Dense/co-located markers are bounded to the existing maximum of 100/day and remain individually selectable through the location list; selection raises the chosen marker above overlaps. No proprietary product layout was copied; research observations and sources are recorded in DESIGN_SYSTEM.

## Routes and secure backend extension

Shared TypeScript contracts define named coordinates, location/marker models, travel modes, waypoints, GeoJSON geometry and metric distance/duration. Conversion boundaries are explicit: provider route input lat,lon; GeoJSON/MapLibre lon,lat. React components never call Geoapify directly.

The local discovery function adds only `location` and `route` operations. Existing search/autocomplete/detail/places contracts and provider adapter remain. Public request bodies contain no trip title, ID, note, traveler or provider key. Server-only provider URLs, exact operations, finite timeout/cancellation, input/output byte limits and sanitized errors isolate credentials. No arbitrary URL/feature forwarding is accepted.

Routes support walking/driving, preserve the supplied activity order, require explicit coordinate confirmation and are calculated only on request. Missing/duplicate coordinate stops are excluded visibly; excessive/far waypoints are rejected. Limit 2–6 stops within 25km of the first. No optimization/avoidance/elevation/premium details is requested. Only provider-supplied complete geometry, leg count/endpoints, distance and duration return; malformed/disconnected/unreachable/partial results fail without a straight-line or invented-time fallback. Accepted display bounds are 500km, 5000 positions and finite metrics. Estimates do not claim real-time traffic. Changing day/order/location/mode hides stale routes until requested again; identical requests reuse memory/server caches. There is no polling, automatic retry or focus/reconnect refetch.

`202611050001_mapping_quota.sql` additively overloads discovery_acquire with p_cost, preserving the Phase 2 tables and old two-argument RPC. It refuses unrecorded collisions and grants only service_role execution. Shared gate/usage/cache transactions enforce the unchanged **100 application-reserved credits/day**, 275ms spacing, 24h cache and 256-entry bounds. Location/discovery misses reserve one; routing conservatively reserves **20**, including failed/cancelled attempts, without refund. Cache hits cost zero. Missing weighted infrastructure fails closed before provider fetch. Actual upstream billing cannot be proven by mocked tests or coordinate bounds; official long-distance pricing examples differ. The conservative reservation and live-verification limitation are documented explicitly in PHASE_5_SETUP.
